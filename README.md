# Mini NPU Simulator

Python 표준 라이브러리만 사용하여 MAC(Multiply-Accumulate) 연산과 간단한 패턴 분류를 체험하는 Windows 콘솔 프로그램입니다. 사용자가 직접 입력한 3×3 행렬을 분류하거나 `data.json`에 저장된 5×5·13×13·25×25 패턴 6개를 자동으로 분석할 수 있습니다.

> 이 프로젝트는 실제 NPU 하드웨어를 제어하거나 딥러닝 모델을 학습하는 프로그램이 아닙니다. NPU에서 자주 사용되는 곱셈-누적 연산의 기본 개념을 Python 행렬 연산으로 단순화해 보여 주는 학습용 시뮬레이터입니다.

## 1. 주요 기능

- **사용자 입력 모드:** 3×3 Cross 필터, X 필터와 분류할 패턴을 입력하거나 패턴 자동 생성기를 사용합니다.
- **JSON 분석 모드:** `data.json`의 테스트 패턴을 읽어 기대 결과와 실제 결과를 비교합니다.
- **MAC 연산:** 같은 위치의 원소를 곱하고 모두 누적합니다.
- **정규화 점수:** 코사인 유사도 방식으로 필터 크기의 영향을 줄여 패턴 모양을 비교합니다.
- **동점 처리:** 사용자 모드는 `판정 불가`, JSON 모드는 `UNDECIDED`를 표시합니다.
- **검증과 리포트:** 행렬 크기, 숫자 자료형, JSON 구조, 패턴 키 및 라벨을 검사하고 PASS/FAIL과 실패 유형을 집계합니다.
- **성능 측정:** 3×3, 5×5, 13×13, 25×25 MAC 평균 시간과 N² 원소 연산 수를 표시합니다.
- **보너스 1:** 2차원 리스트와 1차원 리스트의 MAC 연산 시간을 동일 입력으로 비교합니다.
- **보너스 2:** 원하는 N을 입력해 N×N Cross와 X 패턴을 자동 생성합니다.

## 5. MAC 연산과 분류 원리

### 5.1 MAC (Multiply-Accumulate)

MAC은 두 행렬에서 같은 위치의 원소를 곱한 뒤 결과를 누적하는 연산입니다.

\[
MAC(P,F)=\sum_{i=0}^{N-1}\sum_{j=0}^{N-1}P_{ij}F_{ij}
\]

`P`는 입력 패턴, `F`는 비교할 필터입니다. 각 원소 쌍의 곱을 한 누적 변수에 더해 최종 점수를 계산합니다.

### 5.2 정규화 점수

원시 MAC 합계는 필터 가중치의 크기에도 영향을 받습니다. 이 프로젝트는 다음 코사인 유사도 방식으로 점수를 정규화합니다.

\[
S(P,F)=\frac{MAC(P,F)}{\|P\|_2\times\|F\|_2}
\]

행렬의 L2 크기는 모든 원소를 제곱해 더한 다음 제곱근을 구한 값입니다. 예를 들어 입력 `[1, 0]`과 필터 `[10, 0]`, `[100, 0]`의 원시 MAC 점수는 각각 10과 100이지만 정규화 점수는 둘 다 1.0입니다. 원시 MAC은 누적값이고 정규화 점수는 크기 영향을 줄인 유사도이므로 단위와 스케일이 다릅니다.

### 5.3 동점과 부동소수점 허용 오차

코드는 `EPSILON = 1e-9`를 사용합니다. 두 정규화 점수의 절대 차이가 `0.000000001`보다 작으면 부동소수점 계산 중 발생할 수 있는 미세한 반올림 차이를 동점으로 보고 `UNDECIDED`를 반환합니다. 이 값은 이 프로젝트의 정규화 점수 범위에서 작은 절대 허용 오차로 사용하며, 다른 점수 범위를 사용하는 시스템에서는 상대 오차도 함께 검토해야 합니다.

**모드별 표시와 집계 규칙은 다릅니다.**

| 모드 | 화면 출력 | 결과 처리 |
|---|---|---|
| 사용자 입력 모드 | `판정 불가` | 사용자가 결과를 이해하도록 안내하고 성능 측정으로 이어집니다. |
| JSON 분석 모드 | `UNDECIDED` | 기대 라벨이 `UNDECIDED`이면 PASS, `Cross` 또는 `X`인데 동점이면 FAIL입니다. |

## 6. 사용자 입력 모드

사용자 입력 순서는 다음과 같습니다.

1. Cross 필터의 3개 행 입력
2. X 필터의 3개 행 입력
3. 분류할 패턴을 직접 입력하거나 자동 생성 방식으로 선택

각 행에는 숫자 3개를 공백으로 구분하여 입력합니다. 예시:

```text
0 1 0
1 1 1
0 1 0
```

입력 예시에서 비숫자 `0 a 1`을 입력하면 숫자만 입력하라는 안내가 나오고, `0 1` 또는 `0 1 2 3`처럼 숫자 개수가 맞지 않으면 정확히 3개를 입력하라는 안내가 나온 뒤 재입력을 요구합니다. NaN 또는 무한대 값도 허용하지 않습니다.

분류가 끝나면 Cross/X 원시 MAC 합계, 정규화 점수, 판정 결과와 크기별 성능 요약이 출력됩니다. 사용자 모드의 동점 표시 문구는 `판정 불가`입니다.

## 7. JSON 데이터 분석 모드

JSON 분석 모드는 프로그램 폴더의 `data.json`에서 `filters`와 `patterns`를 읽습니다. 현재 기본 데이터는 다음 6개 패턴으로 구성됩니다.

| 행렬 크기 | 패턴 키 | 개수 |
|---|---|---:|
| 5×5 | `size_5_1`, `size_5_2` | 2 |
| 13×13 | `size_13_1`, `size_13_2` | 2 |
| 25×25 | `size_25_1`, `size_25_2` | 2 |
| 합계 | | **6** |

### 7.1 JSON 구조 예시

실제 행렬에는 각 크기에 맞는 N개 행과 행마다 N개 숫자가 들어가야 합니다. 구조 예시는 다음과 같습니다.

```json
{
  "filters": {
    "size_5": {
      "cross": [[0, 0, 1, 0, 0]],
      "x": [[1, 0, 0, 0, 1]]
    }
  },
  "patterns": {
    "size_5_1": {
      "input": [[0, 0, 1, 0, 0]],
      "expected": "Cross"
    }
  }
}
```

위 코드는 **키 구조만 보여 주는 축약 예시**입니다. 실제 프로그램에 사용할 때는 `cross`, `x`, `input`을 모두 완전한 5×5 행렬로 채워야 합니다.

### 7.2 검증 규칙과 허용 라벨

- 최상위에 `filters`와 `patterns` 객체가 있어야 합니다.
- 각 패턴 키는 `size_N_idx` 형식이어야 합니다. 예: `size_5_1`.
- 프로그램은 키에서 N을 추출해 `filters.size_N`을 찾습니다. 행렬 길이만 보고 크기를 추측하지 않습니다.
- 각 패턴에는 `input`과 `expected`가 있어야 합니다.
- 입력 패턴과 필터는 N×N이고, 모든 원소는 유한한 숫자여야 합니다. 문자열, `True`, `False`, NaN, 무한대는 허용하지 않습니다.
- 필터 키는 Cross 계열(`cross`, `Cross`, `+`, `plus`)과 X 계열(`x`, `X`, `×`)을 정규화해 찾습니다.
- 기대 라벨은 `Cross`, `+`, `plus`, `X`, `×`, `UNDECIDED`, `판정 불가`를 인식합니다.

새 라벨을 추가하려면 `normalize_label()`에 별칭을 등록하고, 필터 선택 및 분류 로직을 확장한 다음, JSON의 `expected`와 테스트 데이터를 추가해야 합니다. 별칭만 추가하고 실제 점수 계산·분류 로직을 추가하지 않으면 새로운 클래스가 완성되는 것은 아닙니다.

### 7.3 PASS/FAIL 및 실패 원인 집계

JSON 모드는 각 테스트의 실제 결과와 기대 결과를 비교합니다. `UNDECIDED`가 `Cross` 또는 `X` 기대값과 다르면 FAIL이며, 실패 원인은 데이터 오류, 동점 판정(UNDECIDED), 일반 판정 불일치로 구분해 집계합니다. JSON 키나 행렬 구조가 잘못된 패턴도 해당 패턴의 데이터 오류로 기록하고 다음 테스트를 계속 처리합니다.

대표적인 실패 원인:

| 오류 | 원인 | 확인 방법 |
|---|---|---|
| `filters` 또는 `patterns` 누락 | JSON 최상위 키가 없음 | 최상위 키 이름 확인 |
| `input` 또는 `expected` 누락 | 패턴 항목 필수 값 누락 | 패턴 객체 확인 |
| 패턴 키 형식 오류 | `size_N_idx`와 다름 | 예: `size_5_1` 형식으로 수정 |
| 크기 불일치 | N×N이 아님 | 행 수와 각 행의 숫자 수 확인 |
| 잘못된 숫자 | 문자열, 논리값, NaN 등 | 유한한 숫자로 수정 |
| 필터 키 누락 | 해당 크기의 Cross 또는 X 필터 없음 | `filters.size_N` 확인 |
| 동점 판정 | 두 정규화 점수 차이가 EPSILON 미만 | 입력·필터가 같은 점수를 내는지 확인 |
| 판정 불일치 | 실제 라벨과 expected가 다름 | 기대 라벨 및 필터 데이터 확인 |

데이터 구조 오류가 발생하면 오류 메시지에 표시된 패턴 키와 경로를 확인해 `data.json`을 수정한 뒤 JSON 분석 모드를 다시 실행합니다.

## 8. 성능 측정

### 8.1 기본 MAC 성능

기본 성능 측정은 크기별 100회 반복하고, `time.perf_counter()`로 MAC 함수 실행 구간을 측정한 뒤 평균 시간을 밀리초(ms)로 표시합니다. 입력, JSON 파일 읽기, 패턴 생성, 콘솔 출력은 이 MAC 시간 측정 구간에서 제외됩니다. 연산 횟수는 한 번의 MAC에서 처리하는 원소 수인 N²입니다.

| 크기 | 원소 연산 수 (N²) |
|---|---:|
| 3×3 | 9 |
| 5×5 | 25 |
| 13×13 | 169 |
| 25×25 | 625 |

사용자가 실행한 측정 예시(2026-11-16, 해당 PC의 1회 실행 결과):

| 크기 | 평균 시간(ms) | N² |
|---|---:|---:|
| 3×3 | 0.001831 | 9 |
| 5×5 | 0.003493 | 25 |
| 13×13 | 0.017788 | 169 |
| 25×25 | 0.039674 | 625 |

이 값은 한 번의 실행 결과이며 다른 PC나 실행 시점에 그대로 재현된다는 보장은 없습니다. 백그라운드 작업, CPU 상태, Python 실행 환경에 따라 측정값은 달라집니다.

### 8.2 보너스 1 - 2차원 / 1차원 배열 비교

- 동일한 생성 패턴으로 두 구현의 MAC 결과가 같은지 먼저 확인합니다.
- 각 크기에서 1,000회씩 실행하고 총 5라운드의 평균을 표시합니다.
- 측정 순서를 라운드마다 바꿔 항상 한 방식이 먼저 실행되는 편향을 줄입니다.
- 1차원 방식은 각 라운드의 2차원→1차원 변환 시간도 포함합니다.
- 변환 비용을 포함하므로 1차원 방식이 항상 더 빠르다고 단정하지 않습니다.

### 8.3 보너스 2 - 패턴 자동 생성기

메인 메뉴에서 `3`을 선택하고 N을 입력하면 Cross와 X 패턴을 생성합니다. Cross는 중앙 행 또는 중앙 열, X는 두 대각선을 1로 만듭니다. 생성 함수는 양의 정수 N을 사용합니다. 다만 매우 큰 N은 화면 출력과 메모리 사용량이 커지므로, 대형 행렬 처리 시 고려할 설계는 아래 10절을 참고합니다.

## 9. 실패 원인 및 시간 복잡도 분석

### 9.1 실패 원인 분석

1. `filters` 또는 `patterns`가 없으면 JSON 최상위 구조 오류가 발생합니다.
2. 패턴 항목에 `input` 또는 `expected`가 없으면 해당 테스트를 처리할 수 없습니다.
3. 패턴 이름이 `size_N_idx` 형식이 아니면 크기 N을 추출할 수 없습니다.
4. 패턴 키에서 추출한 N에 해당하는 `filters.size_N`이 없으면 필터를 찾을 수 없습니다.
5. 입력 행렬의 행 개수가 N과 다르면 크기 검증에 실패합니다.
6. 각 행의 숫자 개수가 N과 다르면 정방 행렬 검증에 실패합니다.
7. 문자열, 논리값, NaN 또는 무한대가 포함되면 숫자 검증에 실패합니다.
8. Cross 또는 X 필터 키가 누락되면 해당 분류 필터를 선택할 수 없습니다.
9. 정규화 점수 차이가 EPSILON보다 작으면 임의로 분류하지 않고 동점으로 처리합니다.
10. 실제 분류 결과와 JSON의 기대 라벨이 다르면 해당 패턴은 FAIL입니다.
11. JSON 테스트는 데이터 오류, 동점 판정, 일반 판정 불일치를 별도 유형으로 집계하여 원인을 확인할 수 있게 합니다.

### 9.2 시간·공간 복잡도

1. N×N 행렬에는 총 N²개의 원소가 있습니다.
2. MAC은 같은 위치의 원소를 한 번씩 곱하고 누적합니다.
3. 따라서 MAC 한 번의 시간 복잡도는 O(N²)입니다.
4. Cross와 X 두 필터를 비교해도 계산량은 상수 배 증가일 뿐 점근적 복잡도는 O(N²)입니다.
5. 정규화 점수 계산도 각 행렬 원소를 순회하므로 O(N²)입니다.
6. 입력 행렬과 필터를 저장하는 데 필요한 공간도 원소 수에 비례하여 O(N²)입니다.
7. N이 두 배가 되면 원소 수와 기본 MAC 연산량은 네 배가 됩니다.
8. 3×3, 5×5, 13×13, 25×25의 원소 수는 각각 9, 25, 169, 625개입니다.
9. 1차원 배열도 모든 원소를 한 번씩 처리하므로 계산 자체의 시간 복잡도는 O(N²)입니다.
10. 1차원 방식에는 변환 비용과 추가 저장 공간이 발생할 수 있으므로 실제 속도는 측정으로 비교해야 합니다.
11. 대형 행렬에서는 계산량뿐 아니라 메모리 대역폭, 객체 오버헤드, 임시 배열 생성 비용이 중요해집니다.

## 10. 대형 행렬(예: 1000×1000) 확장 설계

현재 기본 성능 측정 범위는 3×3부터 25×25까지이며, 1000×1000 실측 시간이나 메모리 사용량을 측정했다고 주장하지 않습니다. 다만 확장 시의 자원 요구량은 다음과 같이 계산할 수 있습니다.

- 1000×1000 행렬 하나는 1,000,000개 원소를 가집니다.
- 원소를 8바이트 float64로 저장한다고 가정하면 순수 수치 데이터는 행렬 하나당 약 8MB입니다.
- 입력 패턴 하나와 Cross/X 필터 두 개를 동시에 보관하면 순수 데이터만 약 24MB입니다.
- Python 중첩 리스트와 개별 float 객체는 추가 오버헤드를 사용하므로 실제 메모리는 24MB보다 커집니다.
- 한 번의 필터 MAC은 1,000,000개의 곱셈·누적 위치를 처리합니다. 두 필터 비교는 대략 2,000,000개 위치를 계산하며, 정규화 계산을 위한 추가 순회도 필요합니다.

확장 시 권장 순서는 다음과 같습니다.

1. 입력 크기 상한과 메모리 사용량 검증을 먼저 둡니다.
2. 불필요한 행렬 복사와 중간 리스트 생성을 줄입니다.
3. 연속된 메모리 배열을 사용하는 구조를 검토합니다.
4. 블록(타일) 단위로 나누어 캐시 재사용을 높이고 작업 집합 크기를 제한합니다.
5. 허용되는 환경에서는 NumPy 등 벡터화 라이브러리 또는 하드웨어 가속 라이브러리를 검토합니다.
6. NPU에서는 메모리에서 연산 장치로 데이터를 이동하는 횟수를 줄이고, 데이터 재사용을 높이도록 블록을 배치합니다.

이 절은 설계 분석이며 1000×1000 실행을 실제로 수행한 벤치마크 결과가 아닙니다.

## 11. CPU 직렬 처리와 NPU 병렬 처리의 병목

현재 Python 코드는 중첩 반복문으로 행과 열을 순서대로 순회하는 CPU 기반 MAC 시뮬레이션입니다. 실제 NPU는 다수의 MAC 연산 유닛을 병렬로 사용해 여러 원소의 곱셈·누적을 동시에 처리하도록 설계됩니다.

| 항목 | CPU 직렬 처리 | NPU 병렬 처리 |
|---|---|---|
| 처리 방식 | 명령과 반복문을 순차 수행 | 다수의 연산 유닛에서 병렬 수행 |
| 강점 | 범용성, 분기·제어 작업 유연성 | 대량 행렬 연산의 처리량 향상 가능 |
| 주요 병목 | 반복문·인덱싱·연산 처리 속도 | 메모리 대역폭, 데이터 이동, 유닛 활용률 |
| 적합한 상황 | 작은 작업과 일반 프로그램 | 반복적인 대규모 MAC·행렬 연산 |

NPU의 연산 유닛이 많아도 항상 빠른 것은 아닙니다. 데이터 공급이 늦거나 메모리 대역폭이 부족하면 연산 유닛이 대기합니다. 작은 3×3 작업에서는 데이터 전달과 실행 준비 비용이 계산 자체보다 커질 수 있습니다. 큰 행렬에서는 블록 단위 데이터 재사용과 병렬 실행으로 이점을 기대할 수 있지만, 실제 성능은 메모리 구조·데이터 형식·하드웨어·실행 라이브러리에 좌우됩니다.

본 프로젝트는 실제 CPU와 NPU의 하드웨어 벤치마크가 아니며, 직렬 MAC 원리와 병렬화 설계상의 장단점을 설명하는 교육용 시뮬레이터입니다.
