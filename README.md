# Mini NPU Simulator

Python 표준 라이브러리만 사용해 MAC(Multiply-Accumulate) 연산과 패턴 분류 과정을 간단히 체험하는 Windows 콘솔 프로그램입니다. 사용자가 직접 입력한 3×3 행렬을 분류하거나, `data.json`에 저장된 5×5·13×13·25×25 패턴 6개를 자동으로 분석할 수 있습니다.

> 이 프로젝트는 실제 NPU 하드웨어를 제어하거나 딥러닝 모델을 학습하는 프로그램이 아닙니다. NPU에서 자주 사용되는 곱셈-누적 연산의 기본 개념을 행렬 점수 계산으로 단순화해 보여 주는 학습용 시뮬레이터입니다.

## 1\. 주요 기능

* **사용자 입력 모드:** Cross 필터, X 필터, 분류할 패턴을 각각 3×3 크기로 입력합니다.
* **JSON 분석 모드:** `data.json`의 6개 테스트 패턴을 읽어 자동으로 분석합니다.
* **MAC 연산:** 패턴과 필터의 같은 위치에 있는 값을 곱하고 모두 더합니다.
* **정규화 점수:** 필터마다 가중치 크기가 다른 영향을 줄이기 위해 MAC 점수를 정규화합니다.
* **테스트 리포트:** 기대 결과와 실제 판정을 비교하고 PASS/FAIL 개수를 출력합니다.
* **성능 측정:** 3×3, 5×5, 13×13, 25×25 크기의 MAC 실행 시간을 측정하고 연산 횟수(N²)를 표시합니다.
* **보너스 1 - 1차원 배열 최적화:** 2차원 배열 기반 MAC과 1차원 배열 기반 MAC을 같은 입력·반복 횟수로 비교합니다. 1차원 방식의 배열 변환 준비 시간도 비교값에 포함합니다.
* **보너스 2 - 패턴 자동 생성기:** N을 입력하면 Cross와 X 행렬을 자동 생성합니다. 생성 패턴은 사용자 입력 모드 및 성능 분석에 재사용됩니다.

```powershell
py --version
```

`main.py`와 `data.json`은 반드시 같은 폴더에 있어야 합니다. 프로그램은 `main.py`가 있는 위치를 기준으로 `data.json`을 찾습니다.

```text
mini-npu-simulator/
├── main.py       # 프로그램 코드
├── data.json     # 필터 행렬과 테스트 패턴 데이터
├── README.md     # 프로젝트 설명 및 실행 안내
└── \*.png         # 실행·테스트·보너스 과제 증빙 스크린샷
```

실행 화면을 캡처한 증빙 이미지도 프로젝트 폴더에 보관하면 제출 자료를 함께 관리할 수 있습니다.

## 4\. 프로그램 실행 방법

1. `mini-npu-simulator` 폴더에 `main.py`와 `data.json`이 있는지 확인합니다.
2. 파일 탐색기에서 해당 폴더를 엽니다.
3. 폴더의 빈 공간을 마우스 오른쪽 버튼으로 클릭하고 **터미널에서 열기** 또는 **PowerShell에서 열기**를 선택합니다.
4. 다음 명령어를 입력합니다.

```powershell
py -X utf8 main.py
```

프로그램 메뉴가 표시됩니다.

```text
================================
       Mini NPU Simulator
================================
1. 사용자 입력 모드
2. JSON 데이터 분석 모드
3. 패턴 자동 생성기 (보너스)
4. 2차원 / 1차원 최적화 성능 비교 (보너스)
```

* `1` 입력: 사용자 입력 모드
* `2` 입력: JSON 데이터 분석 모드
* `3` 입력: 원하는 크기의 Cross와 X 패턴을 출력하는 생성기
* `4` 입력: 2차원 방식과 1차원 방식의 실행 시간을 비교하는 보너스 성능 측정

## 5\. MAC 연산과 패턴 분류 원리

### 5.1 MAC (Multiply-Accumulate)

MAC은 두 행렬에서 같은 위치에 있는 원소를 각각 곱한 다음, 그 결과를 누적해서 더하는 연산입니다.

\[
MAC(P,F)=\\sum\_i\\sum\_j P\_{ij}\\times F\_{ij}
]

여기서 `P`는 입력 패턴, `F`는 비교할 필터입니다. 예를 들어 입력 패턴과 필터의 같은 위치에 `1`과 `0.5`가 있으면 `1 × 0.5 = 0.5`를 누적 합계에 더합니다.

### 5.2 정규화 점수

JSON 데이터의 Cross 필터와 X 필터는 가중치의 크기가 서로 다를 수 있습니다. 원시 MAC 합계만 비교하면 필터 값의 크기가 판정에 지나치게 큰 영향을 줄 수 있으므로, 이 프로그램은 코사인 유사도 방식으로 점수를 정규화합니다.

\[
정규화\\ 점수=\\frac{MAC(P,F)}{|P|\_2\\times|F|\_2}
]

행렬의 L2 크기는 모든 원소를 제곱해 더한 뒤 제곱근을 구합니다. 이 방식으로 입력 패턴과 필터가 얼마나 비슷한 모양으로 겹치는지 비교합니다. 프로그램은 원시 MAC 합계와 정규화 점수를 모두 출력하지만, **최종 분류는 정규화 점수가 더 높은 쪽**으로 결정합니다. 두 점수가 매우 비슷하면 `UNDECIDED`를 반환합니다.

## 6\. 사용자 입력 모드

사용자 입력 모드에서는 다음 순서로 3×3 행렬을 입력합니다.

1. Cross 필터의 3개 행
2. X 필터의 3개 행
3. 분류할 패턴의 3개 행

각 행에는 숫자 3개를 공백으로 구분해 입력합니다. 예시는 다음과 같습니다.

```text
0 1 0
1 1 1
0 1 0
```

테스트에 사용한 입력 예시는 다음과 같습니다.

**Cross 필터**

```text
0 1 0
1 1 1
0 1 0
```

**X 필터 및 분류할 패턴**

```text
1 0 1
0 1 0
1 0 1
```

위 패턴은 X 형태이므로 최종 판정 결과가 `X`로 표시되는지 확인합니다. 입력을 마치면 MAC 합계, 정규화 점수, 최종 판정 및 성능 측정 결과가 출력됩니다.

### 6.1 패턴 자동 생성 기능 재사용

사용자 입력 모드에서 Cross 필터와 X 필터를 입력한 뒤, 분류할 패턴의 입력 방법을 선택합니다.

* `1`: 기존처럼 3×3 패턴을 직접 입력합니다.
* `2`: 자동 생성기를 사용합니다. 이어서 `1`은 Cross, `2`는 X를 선택하면 3×3 패턴을 만들어 분류에 바로 사용합니다.

사용자 입력 모드의 필터 크기는 3×3이므로 이 모드에서 자동 생성해 넣는 패턴도 3×3입니다. 더 큰 크기의 패턴은 메인 메뉴의 `3. 패턴 자동 생성기`에서 만들 수 있습니다.

## 7\. JSON 데이터 분석 모드

JSON 분석 모드에서는 프로그램과 같은 폴더의 `data.json`을 자동으로 읽습니다. 데이터 파일에는 크기별 Cross/X 필터와 테스트 패턴 및 기대 결과가 들어 있습니다.

|데이터 크기|테스트 항목|테스트 수|
|-|-|-:|
|5×5|`size\_5\_1`, `size\_5\_2`|2|
|13×13|`size\_13\_1`, `size\_13\_2`|2|
|25×25|`size\_25\_1`, `size\_25\_2`|2|
|**합계**||**6**|

각 테스트마다 Cross/X의 MAC 합계와 정규화 점수를 계산하고, 실제 판정 결과를 JSON의 기대 결과와 비교합니다. 마지막에 전체 테스트 수, 통과 수, 실패 수와 실패 항목을 출력합니다.

### 최종 테스트 결과

현재 `main.py`와 제공된 `data.json`을 사용해 확인한 결과입니다.

|테스트 항목|기대 결과|실제 결과|상태|
|-|-|-|-|
|`size\_5\_1`|X|X|PASS|
|`size\_5\_2`|Cross|Cross|PASS|
|`size\_13\_1`|X|X|PASS|
|`size\_13\_2`|Cross|Cross|PASS|
|`size\_25\_1`|X|X|PASS|
|`size\_25\_2`|Cross|Cross|PASS|
|**전체**|**6개**|**6개 통과**|**PASS**|

## 8\. 성능 측정 및 보너스 과제

### 8.1 기본 MAC 성능 측정

프로그램은 패턴 생성기를 통해 크기별 Cross 입력 패턴과 X 필터를 만들고, MAC 연산을 각 크기별로 100회 반복 실행합니다. 평균 실행 시간을 밀리초(ms) 단위로 출력하며, 연산 횟수는 행렬의 원소 개수인 `N × N`으로 계산합니다.

|행렬 크기|원소별 곱셈·누적 횟수 (N²)|
|-|-:|
|3×3|9|
|5×5|25|
|13×13|169|
|25×25|625|

실행 시간은 컴퓨터의 성능과 당시 시스템 상태에 따라 달라질 수 있으므로, 제출 시에는 본인 컴퓨터에서 실행한 성능 측정 화면을 증빙으로 사용합니다.

### 8.2 보너스 1 - 2차원 배열과 1차원 배열의 성능 비교

기본 MAC 함수 `mac()`는 행과 열을 차례로 접근하는 2차원 리스트 방식을 사용합니다. 최적화 비교 함수 `mac\_flat()`은 행렬을 행 우선(row-major) 순서로 길이 `N²`인 1차원 리스트로 변환한 뒤 하나의 인덱스로 순차 접근합니다.

```python
# 2차원 리스트 예시
matrix\_2d = \[\[1, 0], \[0, 1]]

# 1차원 리스트 예시(행 우선 순서)
matrix\_1d = \[1, 0, 0, 1]
```

메인 메뉴에서 `4`를 선택하면 3×3, 5×5, 13×13, 25×25에서 두 방식을 비교합니다.

* 크기별 동일한 생성 패턴을 두 방식에 입력합니다.
* 각 방식은 크기별 1,000회씩, 총 5라운드 측정합니다.
* 1차원 방식의 배열 변환 시간도 총 실행 시간에 포함합니다.
* 두 방식의 MAC 결과가 같은지 먼저 검증한 다음 성능을 비교합니다.
* 결과 표에는 2차원 총시간, 1차원 변환+계산 시간, 시간 차이를 표시합니다.

1차원 방식이 항상 더 빠르다고 단정할 수는 없습니다. 실제 측정 결과는 Python 버전, 컴퓨터 상태, 리스트 크기 및 실행 환경에 따라 달라질 수 있으므로 본인 PC에서 출력된 값을 기록합니다.

### 8.3 보너스 2 - 패턴 자동 생성기

메인 메뉴에서 `3`을 선택하고 1 이상의 정수 `N`을 입력하면 `N×N` Cross 패턴과 X 패턴을 출력합니다.

* **Cross:** 중앙 행 또는 중앙 열에 해당하는 칸을 `1`, 나머지를 `0`으로 만듭니다.
* **X:** 왼쪽 위에서 오른쪽 아래로 이어지는 대각선과 오른쪽 위에서 왼쪽 아래로 이어지는 대각선의 칸을 `1`로 만듭니다.

짝수 크기에서는 중앙 기준 인덱스 `N // 2`를 사용합니다. 생성 함수는 사용자 입력 모드에서 3×3 입력 패턴을 자동으로 만드는 데 사용되고, 기본 성능 측정 및 2차원/1차원 최적화 비교에서도 여러 크기의 테스트 행렬을 생성하는 데 재사용됩니다.

## 9\. 오류가 발생했을 때

* **`data.json` 파일을 찾을 수 없다는 오류:** `data.json`이 `main.py`와 같은 `mini-npu-simulator` 폴더에 있는지 확인합니다.
* **`py` 명령을 찾을 수 없다는 오류:** Python 설치 여부와 Windows Python Launcher 설정을 확인합니다.
* **숫자 개수가 맞지 않는다는 안내:** 한 행에 요구된 개수만큼 숫자를 입력하고 숫자 사이를 공백으로 구분합니다. 3×3 모드에서는 한 행에 숫자 3개를 입력합니다.
* **`UNDECIDED` 결과:** Cross와 X의 정규화 점수가 같거나 거의 같은 경우입니다. 입력 패턴과 필터 행렬을 확인합니다.

이번 프로젝트에서는 행렬의 같은 위치 원소를 곱해 누적하는 MAC 연산을 구현하고, 정규화 점수를 이용해 입력 패턴을 Cross 또는 X로 분류했습니다. 사용자 입력 모드와 JSON 기반 자동 분석 모드를 구성했으며, 5×5·13×13·25×25 패턴 6개에 대해 기대 결과와 실제 결과가 일치하는 것을 확인했습니다. 보너스 기능으로 N×N Cross/X 패턴 자동 생성기를 구현하고, 2차원 리스트와 1차원 리스트를 이용한 MAC 연산을 동일 입력 및 반복 횟수로 비교하도록 했습니다. 성능 차이는 실행 환경에 따라 달라지므로 실제 PC의 측정값을 증빙으로 제출합니다.

\## 부록. 실패 원인 및 시간 복잡도 분석



\### 1. 실패 원인 분석



현재 제공된 JSON 데이터의 테스트 6개는 모두 PASS로 확인했습니다. 다만 데이터나 입력 조건이 달라지면 다음과 같은 실패가 발생할 수 있습니다.



1\. JSON 파일에 `filters` 또는 `patterns` 항목이 없으면 데이터 구조 오류가 발생합니다.

2\. 테스트 항목에 `input` 또는 `expected` 값이 없으면 해당 테스트를 정상적으로 처리할 수 없습니다.

3\. 입력 행렬의 행 개수가 설정된 크기 N과 다르면 행렬 크기 검증에서 오류가 발생합니다.

4\. 행렬의 각 행에 들어 있는 숫자 개수가 N과 다르면 잘못된 행렬로 판단합니다.

5\. 행렬에 숫자가 아닌 문자열이나 논리값이 포함되면 숫자 검증에 실패합니다.

6\. 입력 패턴과 비교 필터의 행 또는 열 크기가 다르면 MAC 연산을 수행할 수 없습니다.

7\. JSON에 해당 크기의 Cross 또는 X 필터가 없으면 필터 검색 오류가 발생합니다.

8\. 기대 결과와 실제 분류 결과가 다르면 해당 테스트는 FAIL로 기록됩니다.

9\. Cross와 X의 정규화 점수가 거의 같으면 한쪽으로 임의 판정하지 않고 `UNDECIDED`를 반환합니다.

10\. 입력 데이터의 기대 라벨이 실제 분류 결과와 일치하는지도 확인해야 합니다.

11\. 이러한 오류를 줄이기 위해 행렬 크기, 숫자 자료형, JSON 필수 항목 및 기대 결과를 검증하도록 구현했습니다.



\### 2. 시간 복잡도 분석



1\. MAC 연산은 입력 행렬과 필터 행렬의 같은 위치에 있는 원소를 곱하고 누적합니다.

2\. N×N 행렬에서는 총 N²개의 원소를 확인합니다.

3\. 프로그램은 행과 열을 순회하는 두 개의 반복문으로 MAC 연산을 수행합니다.

4\. 따라서 하나의 MAC 연산에 필요한 시간 복잡도는 O(N²)입니다.

5\. Cross 필터와 X 필터를 각각 비교하더라도 반복 횟수의 상수만 증가하므로 전체 시간 복잡도는 O(N²)입니다.

6\. 정규화 점수를 계산할 때도 행렬의 모든 원소를 순회하므로 시간 복잡도는 O(N²)입니다.

7\. 행렬 크기가 3×3이면 원소 연산 횟수는 9회입니다.

8\. 5×5이면 25회, 13×13이면 169회, 25×25이면 625회로 증가합니다.

9\. 행렬의 한 변의 길이 N이 두 배가 되면 원소 개수는 네 배가 됩니다.

10\. 행렬 자체를 저장하는 데 필요한 공간도 원소 개수에 비례하므로 공간 복잡도는 O(N²)입니다.

11\. 2차원 배열과 1차원 배열 모두 모든 원소를 한 번씩 처리하므로 기본적인 시간 복잡도는 O(N²)입니다.

12\. 1차원 배열은 순차 인덱스로 접근하지만 변환 과정에도 시간이 필요하므로 항상 더 빠르다고 단정할 수 없습니다.

13\. 따라서 실제 성능은 프로그램에서 동일한 입력과 반복 횟수를 사용해 측정하고 비교해야 합니다.



\### 3. 분석 결과



이번 프로젝트에서는 MAC 연산의 기본 구조가 O(N²)임을 확인했습니다. 행렬 크기가 커질수록 계산해야 할 원소 수도 제곱에 비례하여 증가합니다. 또한 배열 저장 방식에 따른 성능 차이는 이론적인 시간 복잡도뿐 아니라 변환 비용과 실행 환경까지 고려해야 한다는 점을 확인했습니다.
